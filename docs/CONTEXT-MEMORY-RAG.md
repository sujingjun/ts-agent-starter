# 上下文、记忆与检索的职责边界

## 从一次真实运行读起

运行 `node dist-core/examples/research-agent.js "MCP 工具授权"`。打开 `src/core/rag.ts`，追踪文档如何分块、生成稳定证据 ID、按租户过滤、搜索和生成引用。

本地检索实现是 Unicode 词项与中文双字词粒度的词频检索，支持相似度组合的辅助函数。**没有把词频向量冒充语义嵌入**。真实嵌入适配和 PgVectorStore 位于 infra，需要配置模型和数据库单独验证。

## 四种不同的数据

当前会话消息用于回答连续问题；RunState 用于恢复执行；NoteMemory 保存有来源、主体与过期时间的显式记忆；Documents/Chunks 保存外部知识。四者都可以持久化，但不能因此互相替代。

不要把临时猜测写成长期事实。新增长期记忆要确定来源、主体、更新与删除策略；用户撤销资料权限后检索不能继续依赖缓存的未授权内容。

## 上下文裁剪

`buildContext` 校验消息调用关系，保留工具调用及其对应结果，按完整 user 组裁剪旧历史。当前组和系统指令放不下时直接报预算错误，而不是截断参数或扔掉安全指令。预算使用 UTF-8 长度估计，**不是供应商精确 Token 计费**。

本包没有实现经过语义评测的自动历史摘要模型。可以增加 ContextCompactor，但须对约束遗漏、证据丢失和虚构摘要进行测试后再启用。不能把简单裁剪命名为“无损压缩”。

## 引用验证两层

第一层：引用 ID 是否来自本次允许的检索证据集，代码已经验证。第二层：正文结论是否真的被引用段落支持，仍需语义评分或人工核查。一个有效链接不能证明陈述正确。

## PostgreSQL 向量练习

执行可选向量迁移，选择一个实际嵌入模型，固定维度与模型版本，写入不同租户的同义资料。验证查询同时过滤 tenant、model 和 dimension；用真实同义词检验召回，而不是只查原句。维度或模型变化必须重建数据，不能直接混用。
